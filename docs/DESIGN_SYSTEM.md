# Design System

`@paon/ui` (`packages/ui`) is the single design system consumed by all
three apps. No app defines its own colors, spacing, typography scale or
base components. A retailer's brand identity is layered on top via
theming, not by forking the design system.

## Principles

- **Quiet, editorial, warm.** Luxury retail's visual language is
  restraint, not decoration. Generous whitespace, a warm neutral
  (not cold gray) palette, and a serif display face paired with a
  clean sans body — evoking a well-printed lookbook more than a SaaS
  dashboard.
- **One token set, three apps.** Tokens are defined once in
  `packages/ui/src/styles/globals.css` using Tailwind v4's CSS-native
  `@theme`. Every app imports `@paon/ui/styles.css`; none redefines a
  color or spacing value.
- **Retailer theming is additive, not a fork.** `Retailer.brandTheme`
  (`accentColor`, `displayFont`, `logoUrl` — see
  [DOMAIN_MODEL.md](./DOMAIN_MODEL.md)) overrides a small, deliberate
  set of tokens per retailer at render time in the Retailer and Customer
  Portals. PAON Admin never applies retailer theming — it always
  renders in the base PAON identity, so platform staff have one
  consistent visual context across every tenant they support.

## Tokens

Defined in `packages/ui/src/styles/globals.css`:

- **Color** — a warm `stone` neutral scale (`oklch`, not RGB/hex, so
  lightness steps are perceptually even) for nearly all UI, a restrained
  `ink` scale for primary actions, and semantic `success` / `warning` /
  `danger` colors. Luxury interfaces should read as monochrome with rare,
  deliberate accent use — not colorful by default.
- **Typography** — `--font-display` (Fraunces, a serif) for headlines
  and moments that should feel considered; `--font-sans` (Inter) for
  UI and body text; `--font-mono` for anything tabular/technical (order
  numbers, SKUs).
- **Radius** — small and restrained (`0.25–0.75rem`). Sharp enough to
  feel considered, not the heavily rounded "app" look.
- **Motion** — one easing curve, `--ease-out-quiet`, used for all
  transitions. Consistency in motion reads as polish; bespoke easing
  per component reads as sloppiness.

`oklch` and CSS `@theme` (Tailwind v4) were chosen over a hand-maintained
hex palette specifically so new shades can be generated by adjusting one
axis (lightness, chroma or hue) predictably — see
[DECISIONS.md](./DECISIONS.md).

## Components

- Built with `class-variance-authority` for variant APIs
  (`<Button variant="primary" size="md">`) and `tailwind-merge` +
  `clsx` (via the `cn()` helper in `packages/ui/src/lib/cn.ts`) so a
  consumer can override classes without specificity fights.
- Every component is headless-friendly where it matters (accepts
  `className`, forwards refs, spreads native props) but is **not** a
  wrapper around a third-party headless library by default — reach for
  Radix primitives only when a component has real accessibility
  complexity (dialogs, comboboxes, menus), not for a button or a card.
- One component, one file, colocated with its variant definitions
  (`Button.tsx` exports both `Button` and `buttonVariants`) so the
  variant API is discoverable from the component itself.
- Components live in `packages/ui/src/components/` and are exported via
  the package's `exports` map as `@paon/ui/components/<Name>` — imported
  directly by name, never through a barrel that forces bundling the
  entire design system into every page.

## Accessibility

WCAG 2.1 AA is the floor, not the target: color contrast is checked
against the token palette (not per-usage), all interactive components
carry visible focus states (`focus-visible:ring-*`, part of every
interactive variant by default), and `eslint-plugin-jsx-a11y` runs as
part of the shared lint config — a component with an accessibility lint
violation does not merge.

## Mobile-first

Every component and layout is designed at the smallest supported
viewport first, then progressively enhanced with `sm:` / `md:` / `lg:`
Tailwind variants. The Customer Portal in particular should be judged
primarily on its phone experience — that is where most customers will
open it.
