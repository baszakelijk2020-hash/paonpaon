# Duplication and Consolidation

Audit-only deliverable. Distinguishes **harmful duplication** (two documents
independently defining the same fact, at risk of drifting apart) from
**intentional summary** (a lower document restates a higher one's conclusion
for local convenience, always citing it), **useful cross-reference**,
**historical repetition** (an archived document repeats something a live
document also says, but the archived copy is inert), and **distinct
contextual treatment** (two documents cover the same named thing for
genuinely different audiences/purposes).

## Repeated ontology / entity descriptions

See `ONTOLOGY_AUDIT.md` for the full per-concept table. Summary of the
duplication-specific findings:

- **Genuinely competing modeling found:** none. The one place that looks
  like duplication at first glance — `Product`/`ProductVariant` (catalog)
  vs. `PhysicalGarment` (owned instance) — is **distinct contextual
  treatment**, not duplication: they model different facts (what-we-sell vs.
  what-a-customer-owns) and are correctly linked by foreign key, not
  independently re-derived.
- **Naming drift, not duplication:** "Self-Portrait" (the founder/product
  term, used in `NORTH_STAR.md`, `docs/FOUNDER_TOOL_BLUEPRINTS.md` FT-05,
  and `docs/RELATIONSHIP_INTELLIGENCE_BLUEPRINT.md`) vs. `CustomerFact` (the
  schema/type name in `packages/domain/src/intelligence/customer-fact.ts`).
  Same concept, two names at two altitudes (product language vs. code
  language) — see `TERMINOLOGY_AUDIT.md`.
- **Multiple disjoint "Proposal" types with no shared abstraction**
  (`CaptureBundleProposal`, `PriceChangeProposal`,
  `ImportEnrichmentFieldProposal`) — this is **distinct contextual
  treatment** at the code level (three genuinely different domains: AI
  capture, alteration pricing, import enrichment) but it means the word
  "Proposal" is not safe to use unqualified anywhere in documentation
  without saying which one. Flagged in `TERMINOLOGY_AUDIT.md`, not treated
  as a defect to fix in code (no evidence a unifying abstraction is needed).
