# Capability Disposition Registry

**Authority:** R0.3 classification of inherited Stage 8–16 work and every
founder-designated tool. This is not a queue and does not authorize work;
`PHASE.md` remains the only sequence. Code and migrations remain factual truth.

Use this registry when a later model encounters a landed type, table, route or
proof and needs to know whether PAON should build on it. The default is never
"continue the old stage because files exist." Find its module and disposition
here, then take the connected slice authorized by `PHASE.md`.

## Disposition vocabulary

- **Keep:** load-bearing shared infrastructure with the right boundary.
- **Harden:** correct strategic capability whose product journey, authority,
  recovery, fidelity or proof is incomplete.
- **Consolidate:** useful work that belongs inside a larger PAON object or
  journey, not as the standalone surface or bounded context it currently is.
- **Replace:** the current experience or contract occupies the right product
  slot incorrectly; retain only independently valid primitives.
- **Quarantine:** preserve the code and learning, but do not expose, activate or
  extend it until the named commercial, legal, provider or product gate clears.
- **Park:** preserve the record and any safe reusable primitives, but remove it
  from the active programme until the founder explicitly reactivates it.
- **Delete:** remove the feature commitment from active plans. Existing code is
  not a promise to extend, expose, or market it.

A disposition is not a completion claim. "Keep" can still require deployment
proof; "Harden" can contain excellent foundations; "Quarantine" is not delete.

## Cross-cutting decisions

1. The Golden Relationship Journey is the first regression spine, not a
   smaller product definition. Every retained capability must attach to a
   shared client, garment, commerce, service or evidence object.
2. Founder tools keep their specified composition and behavior; Atelier Munro
   brand, supplier assumptions and unrelated pitch framing do not transfer.
3. Domain/schema work is a foundation. A visual shell is a shell. Neither is
   "built" until the real multi-role journey joins them and proves state.
4. No provider, partner, hardware, ad, marketplace or cash assumption becomes
   production truth because a local fixture exists.
5. A module can be off, preview, active or suspended without deleting history.
   Jobs, direct routes and Server Actions must enforce the same entitlement;
   navigation hiding alone is not security or product control.
