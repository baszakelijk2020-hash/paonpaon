# 08 — AI

**Snapshot date: 2026-07-29.**

## Package

`packages/ai` — thin OpenAI wrapper. Files: `provider.ts`, `openai-provider.ts`,
`client.ts`, `index.ts`.

## Features implemented

| Feature                                 | Method                          | App wiring                                               | Persist kind             |
| --------------------------------------- | ------------------------------- | -------------------------------------------------------- | ------------------------ |
| Next best action (clienteling)          | `generateNextBestAction`        | Retailer `customers/[id]/actions.ts` + `ai-insights.tsx` | `next_best_action`       |
| Product recommendation (“Today’s Pick”) | `generateProductRecommendation` | Customer `dashboard/actions.ts`                          | `product_recommendation` |

Domain also declares AI generation kind `communication_draft` — **no**
provider method / UI found for it (PROJECT_STATE: deliberately not built).

## Models / providers

- Provider interface: `AIProvider`
- Implementation: `OpenAIProvider`
- Default model string in code: **`gpt-4o-mini`**
- Factory: `createOpenAIClient(apiKey)`
- Apps: `apps/{retailer,customer}/lib/ai.ts` → `getAIProvider()`

ADR-033: OpenAI behind provider-neutral interface.

## Prompt architecture

- **Inline** system/user prompt strings inside `openai-provider.ts`
- **No** separate prompt template files, prompt versioning table, or eval harness
  in this package

## Memory

**Not implemented** as durable preference memory (vision pillar 13). Closest
existing artifacts: `clienteling_notes`, `customer_preferences`, behavioral
events — not an AI memory subsystem.

## Knowledge

**No** knowledge-object store or RAG corpus. Discovery Commerce knowledge
objects exist only in vision docs.

## Embeddings / retrieval

**None** in `@paon/ai` or schema (`pgvector` / embedding columns not found).

## Recommendation logic

`generateProductRecommendation` selects among **caller-supplied candidates**
using product name/description (+ optional weather context). It is **not** a
multi-signal wardrobe engine (vision pillar 10). No collaborative filtering
service found.

## Audit

`ai_generations` table + `AIGenerationRepository`; admin AI monitoring UI.

## Current limitations

- Two narrow LLM features only
- Inputs lack wardrobe twin / metadata graph
- Historically credential-blocked (ADR-051); live OpenAI key state is
  environment-dependent (**unknown from git alone**)
- Unit tests use fakes, not live OpenAI
- No embeddings, no tool-calling agent framework, no memory graph

## Future opportunities (documented only)

See [docs/vision/](../vision/) pillars 06, 10, 13 — **not shipped**.
